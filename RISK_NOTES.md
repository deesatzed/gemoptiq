## Remaining Risks

| Risk | Severity | Why It Matters | Mitigation |
|---|---|---|---|
| Full real Claude/Gemini/Codex model/tool confirmation remains unproven | Medium | PTY behavior is proven with fixtures, safe CLI version probes pass for Codex/Claude/Gemini, and the bounded Claude Code startup trust-prompt smoke passes. The harness has not yet been run against a real model/tool confirmation workflow. | Run `python scripts/real_agent_smoke.py --agent-command "<real model/tool confirmation command>"` only after confirming disposable workspace safety and credentials/account state. |
| Real model JSON-schema adherence is unproven | Medium | The parser now requires structured JSON, but real Gemma output could still include malformed text or fail to follow schema. | Run `venv/bin/python scripts/auditor_smoke.py` in a Metal-capable session and tune prompt/decoding until structured output is reliable. |
| Current execution session lacks Metal access | High | `venv/bin/python scripts/auditor_smoke.py` fails cleanly with `No Metal device available`, so real model load cannot be verified here. | Rerun the real smoke in a local terminal/session with Metal access. |
| Shell Python MLX alias patch differs from repo venv | Medium | `venv/bin/python scripts/sentinel_smoke.py` reports the mapping is present, while `python scripts/sentinel_smoke.py` under miniforge reports it is missing. Running Sentinel outside the venv may fail model loading. | Use `venv/bin/python` or activate `venv` for Sentinel runs; optionally patch/upgrade the shell Python if it must be supported. |
| Nested readiness-run pytest is sandbox-sensitive | Low | `python scripts/readiness_check.py --include-tests` can hit `PermissionError: Operation not permitted: 'ps'` when the root pytest suite is launched from inside another Python subprocess in this managed session, even though direct `pytest -q` passes. | Treat direct `pytest -q` as authoritative in managed sessions; the readiness checker classifies this as externally blocked rather than an app failure. |
| Continuous enforcement is polling-based, not pre-write sandboxing | Medium | The enforcer now detects protected writes after they appear, suspends the runner, and rolls back configured protected-path or built-in secret-path file effects when possible, but it does not prevent the initial write from landing on disk. | Add sandbox-mediated execution or OS-level file access controls if Sentinel needs true pre-write prevention. |
| Command effect extraction is still heuristic | Medium | Sentinel now extracts obvious command text from prompt/history text, JSON command fields, and common Bash tool-call lines, but real agents may use richer protocols or terminal control sequences. | Validate and expand extraction against real Claude/Gemini/Codex protocol output inside disposable workspaces. |
| Approval UX still needs model/tool real-agent validation | Medium | Pending approval now shows the required context, mounted panel, and FIFO queueing in tests, and Claude Code startup prompt/control is proven. The approval flow still has not been validated against real model/tool prompts. | Validate with a disposable real-agent model/tool run when credentials/account/runtime are safe. |
| E2E coverage is mostly synthetic/local | Medium | The aggregate E2E smoke covers the local Sentinel safety loop with disposable fixtures, safe agent CLI metadata probes pass, and Claude Code startup trust-prompt control passes. It still does not prove real Claude/Gemini/Codex model/tool behavior. | Use the guarded real-agent smoke after confirming credentials and disposable workspace safety. |
| Formal release publishing is not defined | Low | Local wheel build is proven, but there is no publish destination, signed artifact policy, or version bump procedure. | Define publishing/versioning after real model and real-agent validation are complete. |
| MCP-Cortex bridge is trace-oriented, not a full MCP proxy | Medium | The bridge records decisions and maps effects, and the docs/runtime UI now disclose that boundary, but it still does not forward or gate actual MCP traffic. | Implement a real MCP adapter/proxy only after the Sentinel local flow is validated with real agents. |
