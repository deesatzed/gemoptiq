What it does

Sentinel wraps a local command, watches what the agent asks to do, classifies risk, and records the session so the human can inspect it later.

Policy gate

Deterministic rules block protected paths, secret-like files, external network commands, and production deploy attempts before model review.

Human approval

The Textual TUI exposes approve, block, pause, kill, and scoped override controls for pending decisions.

Rollback evidence

A no-prompt protected-file write smoke proves Sentinel can suspend the runner and remove the created protected file.

Trace replay

Session JSONL traces capture decisions, effects, user actions, process lifecycle, rollback results, and stable digests.

Proof, not vibes

The project is designed around evidence. The README and GOAL file separate proven behavior from remaining gaps.

Clear safety boundary

Sentinel is local supervision. It is useful because it is practical, inspectable, and evidence-backed. It is not a formal sandbox.

It can supervise

Launch a local process, classify effects, ask for approval, suspend/kill the runner, and write traces.

It can react

Polling enforcement can detect protected file effects after they appear and roll back supported protected writes.

It cannot guarantee containment

It is not a kernel sandbox, a container boundary, a cloud authorization service, or a replacement for safe disposable workspaces.

Try it locally

Install the package, inspect readiness, run a harmless command, then replay the trace.

pip install -e .
sentinel check-env
sentinel readiness --no-run
sentinel run --config sentinel.yaml -- python -c "print('ready')"
sentinel trace replay --format text .sentinel/traces/<session>.jsonl
Cortex Sentinel is a local-first safety console. Use disposable workspaces for real-agent validation and keep secrets out of prompts and traces.
